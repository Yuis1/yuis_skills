# 组织并行工作

## 判断是否派发

先遵守用户与当前运行环境的派发限制。仅派发可独立推进且收益超过启动、交接和集成成本的工作。常规规划由父 Agent 完成；顾问或委员会须有具体未决问题或用户明确要求。

默认仅根 Agent 派发：Worker 和 Reviewer 向父 Agent 报告所需协助，不再自行派发分离的 Agent。当用户针对多子系统复杂工程显式授权分层委派时，指定领域的 Lead 可向直接 Worker 分派有边界任务；叶子节点 Worker 不得进一步递归派发。

根总控负责目标收敛、架构与契约锁定、任务切片分派、验收裁决与资产闭环；总控不亲自承担叶子节点的具体编码与调试，避免深陷实现细节而丧失全局把控。将具体实现、局部修复与测试执行交由有界 Worker，根总控专注于清除全局瓶颈、把控交付质量与强制回收脱管资产。

## 二级总控与领域领队机制

当快节奏并行开发需要协同多个子系统（如客户端、服务端、数据、测试与基础设施）时，启用深度严格锁定为两层的二级总控架构：

1. **一级总控（Root Orchestrator）：** 负责锁定跨领域公有 Schema、划分 2~4 个架构领域、任命高推理能力的领域领队（Domain Lead），并仲裁里程碑集成。总控绝不亲自编写叶子代码，亦不直接穿透审阅叶子原始日志。
2. **二级总控（Domain Lead）：** 由高等级模型（如 Sol 或 Astra）担当，独占负责单一架构领域。领队将领域目标切片为原子任务，管理下辖 3~6 个直接叶子 Worker，分配隔离的临时环境，并执行领域级质量门禁。领队严禁单方面篡改共享公有契约。
3. **叶子执行者（Leaf Worker）：** 在专属工作树中执行单一有界任务契约。叶子节点硬性禁止再次派发子智能体（截断递归派发）。
4. **级联摘要隔离：** 叶子 Worker 仅向二级总控提交结构化交接单（`git diff --stat`、测试命令、退出码与输出摘要）；二级总控在领域内验证通过后，仅向一级总控汇报精炼的领域里程碑摘要。
5. **分层工作树拓扑与闭环：** 主干集成领域分支；各二级总控持有一棵领域集成分支与工作树；各叶子 Worker 持有一棵临时工作树。叶子任务合入领域分支时，立即删除叶子工作树与分支；领域里程碑合入主干时，一级总控打标恢复并回收二级工作树。
6. **领域死锁熔断：** 当同一任务下连续 2 个叶子 Worker 尝试失败或反复横跳时，二级总控必须熔断该子工作流，提取失败的技术假设，向一级总控升级请求架构重新裁决。

## 以任务契约绑定执行者

明确目标、输入或候选版本、读写边界、验收检查、升级阈值以及资产去向计划（目标集成线、所需恢复标签以及分支与工作树的退役条件）。在此 `Task Contract` 范围内，Worker 享有对内部调用链修复、私有适配器与本地测试的自治闭环权，无需因常规小修反复暂停申请许可。

仅在触发以下关键副作用时向父级升级：
- 引入超出契约范围的公有协议或跨组件 API 变更；
- 访问未授权的外部网络端点、跨域凭据或提权操作；
- 执行不可逆的持久化变更或破坏性文件覆盖；
- 遭遇 `dcg` 或权限等工具执行拦截。确认在授权范围内安全受控时，优先拆分成针对性小命令或使用 `dcg` 白名单/allow-once 放行；确认存在越权破坏风险时必须停止并升级报告。

模型和强度未指定时读取可用的 `delegation-models`；用户明确选择优先。派发专业视角任务时（如对抗性审查或取证核验），分配具体的工程方法论、工具与证据标准；避免空洞的角色扮演。直接使用当前运行环境暴露的工具 Schema（`paseo`、Codex 原生委派或 CLI）。

## 隔离写入与权限

- 每个工作树同时最多一个活动写入方，与权限模式无关。并发写入使用不同工作树；Reviewer 未获其他授权时保持只读。
- 使用足以完成已授权任务的权限。仅因测试需要写入本地缓存，并不意味着必须开放主机级权限；模式名称不是隔离证明。
- 创建新分支前记录基线提交 SHA，创建后核对 HEAD 与 merge-base。使用既有分支或 PR 时直接核对目标引用和比较基线。
- 将工作树生命周期作为临时租约管理。为并发工作树分配独立的临时端口、套接字路径或测试数据库，避免运行时端口碰撞。任务合并或放弃后及时移除工作树以释放分支锁、工作树元数据和磁盘空间；派发新并发前先清理陈旧或孤儿工作树。
- 解耦源码留存、活动分支与工作目录。留存历史依赖提交 SHA 或轻量级标签，而非长期占据活动分支或持续检出。针对待决资产的 HOLD 必须精确到具体文件并附带显式解除条件，严禁以此为借口无限期冻结整棵工作树或整个分支。

## 延续、恢复与结束

对原子任务契约优先使用短命、无状态的 Worker 会话，避免长时间连续会话引发上下文腐化。任务验收后及时回收 Worker 会话；仅在任务、相关上下文和权限边界完全一致时才复用既有会话。向继任总控执行会话交接时，暂停或取消前任的活跃 Goal 与周期性心跳，防止双总控脑裂并行调度。

重试前先区分失败原因，仅在任务预算内重试安全的临时故障。在遭遇连续修复失败或反复横跳时触发上下文中毒熔断：不在同一污染会话中堆叠错误推演，而是回退至基线、提取明确的负向约束、启动全新的冷启动会话。外部提交可能已发生时，查询状态或记录不确定性，严禁盲目重发。直接修复缺失输入与工具缺陷；更换模型或盲目等待无法解决工具故障。

防止根总控上下文膨胀：根 Agent 仅审阅结构化交接单、退出状态与 `git diff --stat`，子 Agent 的原始推理过程与构建控制台日志留在其独立日志中。依据事件 ID 或状态哈希对完成通知与心跳进行去重。对无变化的重复心跳进行幂等吸收，不生成重复冗长的叙事报告，也不重新派发相同工作。Worker 完成通知仅是进度事件，不代表根目标完成。核对并整合结果，检查根目标剩余瓶颈，并在未遇实质决策阻碍时继续推进已授权工作。在具有实质意义的里程碑汇报。将集成与退役同批闭环：仅当分支已合并或完成恢复打标、且临时工作树已删除时，子任务才算真正完成；严禁让临时环境的创建速度无限领先于回收速度。
