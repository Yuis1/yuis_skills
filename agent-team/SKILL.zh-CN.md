# 组织并行工作

## 判断是否派发

先遵守用户与当前运行环境的派发限制。仅派发可独立推进且收益超过启动、交接和集成成本的工作。常规规划由父 Agent 完成；顾问或委员会须有具体未决问题或用户明确要求。

只有根 Agent 派发。子 Agent 和 Reviewer 向父 Agent 报告所需协助，不再创建其他 Agent，包括脱离父级的 Agent 或通过另一工具启动的 Agent。

对于持续性目标，根 Agent 直接负责一项能实质推进目标的工作。派发能推进目标的成果任务，避免连续派发细小后续任务，以免根 Agent 只负责协调工作和审核结果。

## 给出有边界的任务

说明目标、输入或候选版本、读写范围、验收检查、禁止的副作用及返回内容。模型和强度未指定时，读取可用的 `delegation-models`；用户明确选择优先。不得为了子任务修改父会话模型、手工模型选择界面或全局配置。

使用当前运行环境暴露的工具 Schema；使用 Paseo 时读取已安装的官方 `paseo` 技能。Codex 原生委派与 Paseo 创建接口不同，不互相照抄参数，也不猜测不可用选项。工作区位置与父子关系是不同概念。

## 隔离写入与权限

- 每个工作树同时最多一个活动写入方，与权限模式无关。并发写入使用不同工作树；Reviewer 未获其他授权时保持只读。
- 使用足以完成已授权任务的权限。仅因测试需要写入缓存，并不意味着必须开放全部主机访问权限；模式名称也不是隔离证明。
- 创建新分支前记录已解析的基线 SHA，创建后核对 HEAD 与 merge-base。使用既有分支或 PR 时核对目标引用和比较基线，不要求其 HEAD 等于基线。

## 延续、恢复与结束

任务、相关上下文和权限边界仍一致时复用会话。独立审查或任务大幅变化时使用新上下文；交接时提供证据指针摘要，不在每次换模型前机械压缩。

重试前先区分失败原因。仅在任务预算内重试可安全执行的临时失败操作。外部提交可能已发生时，查询状态或报告不确定性，不能盲目重发。缺少输入和工具故障需要针对性处理，更强模型或固定等待不能替代修复。

工具支持时使用完成通知；通知失效、预算到期或用户询问时允许有限状态查询。子 Agent 完成通知只是结果事件，不是新的用户目标，也不代表根目标完成。核对并整合结果后，重新查看原始目标，按剩余瓶颈选择下一动作。除非目标已完成、用户要求暂停或确实需要决策，否则继续已授权工作。按有意义的里程碑汇报，不要每收到一个子任务结果就结束根 Agent 的当前回合。读取结果后再归档，预期有后续工作时保留会话。父 Agent 核对结果并记录缺口，只表示该子任务完成，不表示根目标完成。
