# 组织并行工作

## 判断是否派发

先遵守用户与当前运行环境的派发限制。仅派发可独立推进且收益超过启动、交接和集成成本的工作。常规规划由父 Agent 完成；顾问或委员会须有具体未决问题或用户明确要求。简单任务严禁启动多智能体派发：单文件修改、局部缺陷修复或涉及模块少于 3 个的常规任务由单一会话直接执行。多智能体编排严格限定于真正的跨边界并行工作流。

默认仅根 Agent 派发：Worker 和 Reviewer 向父 Agent 报告所需协助，不再自行派发分离的 Agent。当用户针对多子系统复杂工程显式授权分层委派时，指定领域的 Lead 可向直接 Worker 分派有边界任务；叶子节点 Worker 不得进一步递归派发。

根总控纯粹运行于控制面（Control Plane，负责目标收敛、跨域契约锁定、验收仲裁与资产退役）；数据面（Data Plane，具体实现、局部修复与测试运行）全部分离给有界 Worker。根总控依据真实产品行为验证判定交付，严禁让内部监控探针或脆弱治理工具的读数噪声绑架产品交付进度。

强制执行去官僚化棘轮（Anti-Bureaucracy Ratchet）：元工作（任务追踪、契约商定、审查报告与测试脚手架修补）的存在仅为降低产品代码交付风险，绝非留存资产本身。严禁在工作区或临时目录沉降仪式性的关闭凭据（Closeout）、抽样转储或多阶段元数据文件；所有任务交接必须依托瞬态结构化输出与简明提交摘要完成。在连续多个集成提交均未触及产品核心源码路径时（完全被脚手架修补、端口冲突或审查死循环吞噬），必须触发元工作熔断（Meta-Work Circuit Breaker）：总控立即叫停并行派发，将脚手架复杂度坍缩为最小直接运行器，强行恢复对主线产品代码的交付聚焦。

## 二级总控与领域领队机制

当快节奏并行开发需要协同多个子系统（如客户端、服务端、数据、测试与基础设施）时，启用深度严格锁定为两层的二级总控架构：

1. **一级总控（Root Orchestrator）：** 负责锁定跨领域公有 Schema、划分 2~4 个架构领域、任命高吞吐战术领域领队（优先采用 `pi/deepseek-official/deepseek-flash`），并仲裁里程碑集成。总控绝不亲自编写叶子代码，亦不直接穿透审阅叶子原始日志。
2. **二级总控（Domain Lead）：** 敏捷、克制的战术总控模型，独占负责单一架构领域（默认采用兼具成本优势的 `codebuddy/deepseek-v4.1-flash`；必要时退回 Pi 原厂通道）。领队将领域目标切片为原子任务，管理下辖 3~6 个直接叶子 Worker，分配隔离的临时环境，并执行领域级质量门禁。领队严禁单方面篡改共享公有契约。一级总控与二级领队恪守叶子环境完全自治（Decentralized Leaf Autonomy）：仅把关完成定义（Definition of Done）与最终黑盒验收，局部临时配置、动态端口分配与内部测试运行器完全下放叶子 Worker 自治，总控严禁插手微观测试脚本实现。
3. **开发计划规划与任务切片拆解：** 开发计划由 `pi/deepseek-official/deepseek-flash`（思考等级：`high`；其他 DeepSeek 渠道兜底）主导，梳理端到端黄金路径路线图并拆解为 3~6 个以单一事务边界为核心的原子任务契约，锚定单命令端到端真实验收。`pi/openai-codex/gpt-6-astra` 通过 `/skill:paseo-advisor` 提供不变量边界的参考建议，不作为强制阻断门禁。
4. **专家顾问热线（Hardcore Technical Advisor Hotline）：** 当 Worker 或领队遭遇深水区并发死锁、协议底层硬伤或不可复现算法阻碍时，领队通过 `/skill:paseo-advisor` 咨询专家顾问（`pi/openai-codex/gpt-6-astra`，按需采用 `high` 或 `xhigh` 思考等级）获取只读第二意见破局。该咨询过程不涉及主控权交接，战术领队始终独占编排主控权，严禁将重型模型长期挂在主控席位或交出控制权。
5. **推理等级弹性配置（Reasoning Effort Allocation）：** 总控、领队与常规规划者默认采用 `high` 思考等级，保障交付吞吐并避免推测性辩论死循环；极高推理等级（`xhigh` 或 `max`）仅在底层深度死锁、复杂并发竞态或形式化加密校验等硬核难题攻坚时针对性启用。
6. **叶子执行者（Leaf Worker）：** 在专属工作树中执行单一有界任务契约。核心业务开发默认采用 `pi/openai-codex/gpt-6.1-sol`，仅低难度重复性机械任务走 `pi/openai-codex/gpt-6.1-terra`。叶子节点硬性禁止再次派发子智能体（截断递归派发）。
7. **级联摘要隔离：** 叶子 Worker 仅向二级总控提交结构化交接单（`git diff --stat`、测试命令、退出码与输出摘要）；二级总控在领域内验证通过后，仅向一级总控汇报精炼的领域里程碑摘要。
8. **分层工作树拓扑与闭环：** 主干集成领域分支；各二级总控持有一棵领域集成分支与工作树；各叶子 Worker 持有一棵临时工作树。叶子任务合入领域分支时，立即删除叶子工作树与分支；领域里程碑合入主干时，一级总控打标恢复并回收二级工作树。
9. **领域死锁熔断：** 当同一任务下连续 2 个叶子 Worker 尝试失败或反复横跳时，二级总控必须熔断该子工作流，提取失败的技术假设，向一级总控升级请求架构重新裁决。

## 以任务契约绑定执行者

明确目标、输入或候选版本、读写边界、验收检查、升级阈值以及资产去向计划（目标集成线、所需恢复标签以及分支与工作树的退役条件）。在此 `Task Contract` 范围内，Worker 享有对内部调用链修复、私有适配器、本地测试以及测试夹具修复的自治闭环权，无需因常规小修反复暂停申请许可。自治闭环显式包含修复内部验证脚本、测试控制器与临时支撑构件；严禁将内部测试工具的局部修补升级向用户询问，除非触碰关键副作用红线。恪守单命令端到端真实验收最高原则（Single-Command E2E Primacy）：子系统与解耦切片通过（后端单元、UI 组件 Mock）仅为中间证明；只有当单条可重现命令完整跑通未经 Mock 的端到端真实用户路径时，才允许计入里程碑完成。

落实极简 4 态看板（Canonical 4-State Taskboard）：任务状态跟踪的状态机严格限定为 `TODO`、`IN_PROGRESS`、`DONE`、`BLOCKED` 四种标准值。严禁在看板上生造复合、过渡性的官僚状态（如多阶段关闭或审查前缀）。针对重型依赖执行桩化解耦交付（Stub-Decoupled Delivery）：当未校准的复杂 AI 模型、重型算法或第三方支付资质阻碍里程碑交付时，总控必须冻结接口契约并注入确定性的规则桩（Rule-based Stub），优先跑通未经 Mock 的主干黄金路径，严禁让整个团队停摆在外部研究循环上。

仅在触发以下关键副作用时向父级升级：
- 引入超出契约范围的公有协议或跨组件 API 变更；
- 访问未授权的外部网络端点、跨域凭据或提权操作；
- 执行不可逆的持久化变更或破坏性文件覆盖；
- 遭遇 `dcg` 或权限等工具执行拦截。确认在授权范围内安全受控时，优先拆分成针对性小命令或使用 `dcg` 白名单/allow-once 放行；确认存在越权破坏风险时必须停止并升级报告。

模型和强度未指定时读取下方的认知模型委派矩阵；用户明确选择优先。派发专业视角任务时（如对抗性审查或取证核验），分配具体的工程方法论、工具与证据标准；避免空洞的角色扮演。直接使用当前运行环境暴露的工具 Schema（`paseo`、Codex 原生委派或 CLI）。

## 隔离写入与权限

- 每个工作树同时最多一个活动写入方，与权限模式无关。并发写入使用不同工作树；Reviewer 未获其他授权时保持只读。
- 使用足以完成已授权任务的权限。仅因测试需要写入本地缓存，并不意味着必须开放主机级权限；模式名称不是隔离证明。
- 创建新分支前记录基线提交 SHA，创建后核对 HEAD 与 merge-base。使用既有分支或 PR 时直接核对目标引用和比较基线。
- 将工作树生命周期作为临时租约管理。为并发工作树分配独立的临时端口、套接字路径或测试数据库，避免运行时端口碰撞。任务合并或放弃后及时移除工作树以释放分支锁、工作树元数据和磁盘空间；派发新并发前先清理陈旧或孤儿工作树。
- 解耦源码留存、活动分支与工作目录。留存历史依赖提交 SHA 或轻量级标签，而非长期占据活动分支或持续检出。针对待决资产的 HOLD 必须精确到具体文件并附带显式解除条件，严禁以此为借口无限期冻结整棵工作树或整个分支。

## 推进、恢复与收尾

偏向使用针对单一原子任务契约的无状态、短会话 Worker，避免长达数小时易发生上下文腐化的长会话。任务验收后及时回收 Worker 会话；仅在任务目标、相关上下文和权限边界完全一致时才复用既有会话。当向后继会话移交总控角色时，暂停或取消前任的活动目标和周期性心跳，防止出现裂脑双重编排。

重试前先对失败进行分类，仅在任务预算内重试安全的瞬态操作。在多次修复失败或 diff 反复横跳时触发上下文中毒熔断：不再同一会话内复合错误推理，而是回滚至基线，提取明确的负向约束，使用全新会话执行净室重启。若外部动作可能已经发生，先查询其状态或记录不确定性，绝不盲目重发。直接处理缺失的输入与工具缺陷；更换模型或盲目等待无法治愈损坏的工具。

保护一级总控免受上下文膨胀：总控仅审查结构化交接单、退出码与 `git diff --stat`，子智能体的原始推理与构建日志留在 Worker 本地。按事件 ID 或状态哈希对完成通知与心跳去重。幂等吸收未变的心跳，不输出重复的叙述性汇报，亦不重新派发相同工作。Worker 完成通知仅是进度事件，不是总控目标已完成的证明。复核并集成结果，排查剩余瓶颈，并在未被决策阻断时继续推进授权工作。在有意义的里程碑汇报。将集成与退役成对绑定：仅当分支已合并或打标留存，且临时工作树已删除时，Worker 任务才算完成；防止临时环境的创建速率永久超出回收速率。

## 认知模型委派矩阵

仅在用户未显式指定委派 Agent 的模型或推理强度时使用这些默认设置。尊重用户的明确选择。不更改父级 Agent 的模型、推理强度或手动模型选择器。本矩阵不构成委派授权；首先遵循上方的委派与团队规则。不强行套用角色名称。除非明确要求，否则关闭快速模式。

### 领域模型特化分工

1. **顶层系统架构设计与不变量建模：**
   - 使用 `pi/openai-codex/gpt-6-astra`（默认 `high`；仅在硬核死锁时保留 `xhigh` 极高推理）。
   - 产出形式化类型、状态机与接口契约（`Schema-as-Spec`），拒绝推测性自然语言。
2. **架构审查与去冗余瘦身：**
   - 使用 `antigravity/gemini-4-hydrogen-high`（通过 Paseo 的官方 Antigravity CLI 通道；推理强度编码在模型 ID 中，省略 `thinkingOptionId`）。
   - 依托全局上下文审视跨模块依赖，在代码生成前主动修剪过度防御的分支、多余校验层与偶发复杂度。
3. **开发计划规划与范围拆解：**
   - **计划规划主笔引擎：** 使用 `pi/deepseek-official/deepseek-flash`（思考等级：`high`；其他渠道的 DeepSeek 如 `codebuddy/deepseek-v4.1-flash` 作为兜底）。由其主导宏观里程碑路线图与端到端黄金路径，果断剔除历史负债，锚定单命令 E2E 验收，并将当前里程碑细化为 3~6 个原子任务契约。
   - **架构不变量顾问参考：** 咨询 `pi/openai-codex/gpt-6-astra`（通过 `/skill:paseo-advisor`）作为领域不变量边界与状态转换的补充参考。Astra 严格作为顾问，不作为强制阻断门禁。
4. **战术编排分层架构：**
   - **一级总控（Tier 1）：** 使用 `pi/deepseek-official/deepseek-flash`（依托原生 1M 上下文保障高前缀缓存命中率、跨域契约锁定与里程碑集成）。
   - **二级领队（Tier 2）：** 默认采用 `codebuddy/deepseek-v4.1-flash`（高性价比战术切片、敏捷看板跟踪与工单监督；不可用时退回 Pi 原厂通道）。
5. **深水区硬核排障与死锁突破：**
   - 咨询 `pi/openai-codex/gpt-6-astra`（思考等级：`high`，通过 `/skill:paseo-advisor`）作为只读第二意见顾问，攻坚深水区并发竞态、协议底层硬伤或不可复现死锁。战术领队全程保持编排主控权，不让渡控制权或移交任务。
6. **文案撰写、市场宣发、产品文档与宏观调研：**
   - 文案使用 `antigravity/gemini-4-hydrogen-medium`，PRD 与文献调研使用 `antigravity/gemini-4-hydrogen-high`（通过 Paseo 的官方 CLI 通道；省略 `thinkingOptionId`）。
   - 表达自然、无代码防御偏见，在大文本集合上保持极高综合吞吐。
7. **代码编写与核心实现模型：**
   - **核心主力模型：** 默认采用 `pi/openai-codex/gpt-6.1-sol`（思考等级：`high`）。承接实质性业务特性开发、纵向切片 TDD、复杂重构与状态机实现。
   - **低难度机械任务：** 路由至 `pi/openai-codex/gpt-6.1-terra`（思考等级：`low` 或 `medium`）。用于样板代码生成、机械编辑、提交信息规范与元数据更新。
8. **代理网关截断边界限制：**
   - 第三方模型经由多租户代理网关包装时，上下文窗口常常被截断至 16k~32k 并伴随有损压缩。严禁将代理网关转发的第三方模型用作全局总控或多文件规划器；此类模型严格限定于局部单文件编辑。
