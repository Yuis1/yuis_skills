# 组织并行工作

## 判断是否派发

先遵守用户与当前运行环境的派发限制。仅派发可独立推进且收益超过启动、交接和集成成本的工作。常规规划由父 Agent 完成；顾问或委员会须有具体未决问题或用户明确要求。

默认仅根 Agent 派发：Worker 和 Reviewer 向父 Agent 报告所需协助，不再自行派发分离的 Agent。当用户针对多子系统复杂工程显式授权分层委派时，指定领域的 Lead 可向直接 Worker 分派有边界任务；叶子节点 Worker 不得进一步递归派发。

根 Agent 必须直接负责一项能实质推进目标的关键工作线。派发可落地的具体成果任务，避免连续派发微小任务而导致根 Agent 退化为单纯的状态转发与签收瓶颈。

## 以任务契约绑定执行者

明确目标、输入或候选版本、读写边界、验收检查与升级阈值。在此 `Task Contract` 范围内，Worker 享有对内部调用链修复、私有适配器与本地测试的自治闭环权，无需因常规小修反复暂停申请许可。

仅在触发以下关键副作用时向父级升级：
- 引入超出契约范围的公有协议或跨组件 API 变更；
- 访问未授权的外部网络端点、跨域凭据或提权操作；
- 执行不可逆的持久化变更或破坏性文件覆盖；
- 遭遇 `dcg` 或权限等工具执行拦截。确认在授权范围内安全受控时，优先拆分成针对性小命令或使用 `dcg` 白名单/allow-once 放行；确认存在越权破坏风险时必须停止并升级报告。

模型和强度未指定时读取可用的 `delegation-models`；用户明确选择优先。派发专业视角任务时（如对抗性审查或取证核验），分配具体的工程方法论、工具与证据标准；避免空洞的角色扮演。直接使用当前运行环境暴露的工具 Schema（`paseo`、Codex 原生委派或 CLI）。

## 隔离写入与权限

- 每个工作树同时最多一个活动写入方，与权限模式无关。并发写入使用不同工作树；Reviewer 未获其他授权时保持只读。
- 使用足以完成已授权任务的权限。仅因测试需要写入本地缓存，并不意味着必须开放主机级权限；模式名称不是隔离证明。
- 创建新分支前记录基线提交 SHA，创建后核对 HEAD 与 merge-base。使用既有分支或 PR 时直接核对目标引用和比较基线。
- 将工作树生命周期作为临时租约管理。为并发工作树分配独立的临时端口、套接字路径或测试数据库，避免运行时端口碰撞。任务合并或放弃后及时移除工作树以释放分支锁、工作树元数据和磁盘空间；派发新并发前先清理陈旧或孤儿工作树。

## 延续、恢复与结束

对原子任务契约优先使用短命、无状态的 Worker 会话，避免长时间连续会话引发上下文腐化。任务验收后及时回收 Worker 会话；仅在任务、相关上下文和权限边界完全一致时才复用既有会话。

重试前先区分失败原因，仅在任务预算内重试安全的临时故障。在遭遇连续修复失败或反复横跳时触发上下文中毒熔断：不在同一污染会话中堆叠错误推演，而是回退至基线、提取明确的负向约束、启动全新的冷启动会话。外部提交可能已发生时，查询状态或记录不确定性，严禁盲目重发。直接修复缺失输入与工具缺陷；更换模型或盲目等待无法解决工具故障。

防止根总控上下文膨胀：根 Agent 仅审阅结构化交接单、退出状态与 `git diff --stat`，子 Agent 的原始推理过程与构建控制台日志留在其独立日志中。依据事件 ID 或状态哈希对完成通知与心跳进行去重。对无变化的重复心跳进行幂等吸收，不生成重复冗长的叙事报告，也不重新派发相同工作。Worker 完成通知仅是进度事件，不代表根目标完成。核对并整合结果，检查根目标剩余瓶颈，并在未遇实质决策阻碍时继续推进已授权工作。在具有实质意义的里程碑汇报，成果集成后及时清理临时工作树与子会话。
