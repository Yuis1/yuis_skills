# Agent 开发

## 定义并验证变更

对提示词、模型、Schema、工具和编排变更进行版本管理。明确预期行为、代表性案例，以及需要解决的问题或降低的成本；用相同的相关输入比较候选，报告回归与证据缺口。

增加提示规则前，先诊断输入、上下文、工具和任务边界。已知原因直接修复；只有实测收益足以抵消新增工作量时才添加编排步骤。遵循既有模型政策，不另外维护一套默认值。

语义决策使用语义判断。确定性解析、标识符、授权校验与可审计协议规则仍采用确定性逻辑，不用脆弱关键词匹配伪装成模型推理。

## 按可验证单元生成并检查

根据任务和可用验证反馈选择输出规模。完整文件或机械转换可以一次生成。较长或不确定的工作拆成可独立检查的单元，检查结果后继续。只有重复结构确有收益时才使用 JSON 与可信模板。不得以模拟工具输出替代执行证据，也不要求披露私有推理过程。

## 确保提示词与任务相关

使用目标角色能理解的语言，仅在实现细节中的名称有助于该角色决策时才提及。删除废弃字段、始终为空的输出和过时供应商格式；兼容性由运行时负责。

必要时保持可复用指令稳定，但不能为了缓存收益而改变语义或指令优先级。声称性能改善前核实供应商的缓存行为。

交付行为变化、比较案例、实际结果和剩余限制。配置或集成结论使用 `test-evidence`；模型可用本身不能证明任务质量。
