# Agent 开发

## 定义并验证变更

对提示词、模型、Schema、工具和编排变更进行版本管理。使用代表性案例建立行为评估基准（Eval），在相同输入下比较候选方案，衡量回归、成本与证据缺口。

增加提示词规则前，先诊断输入、上下文、工具和任务边界。已知根因直接用确定性工具修复，而非叠加脆弱的提示词补丁。针对反复出现的失效模式设计 Agent 时，提供自主验证所必需的底层支撑（如原始 Trace 抓取、Commit 状态映射追踪、隔离的复现与测试环境），使模型能够独立复现、修复并验证。

语义决策使用语义判断。确定性解析、状态索引、授权校验与可审计协议规则仍采用确定性代码逻辑，不用脆弱关键词匹配伪装成模型推理。

## 按可验证单元生成并检查

根据任务规模与可用验证反馈选择生成单元大小。完整文件或机械转换可以一次生成；较长或不确定的工作拆成可独立检查的单元，并在继续前检查每一步结果。只有重复结构确有收益时才使用带可信 Schema 的 JSON。强制采用真实工具执行证据，严禁使用模拟工具输出或模型口头自我认证。

## 确保提示词与任务相关

围绕角色的领域词汇组织指令，仅在工具调用需要时提及底层实现细节。删除废弃字段、始终为空的输出和过时的供应商格式。依靠确定性的运行时工具处理状态追踪、超时控制与日志记录，而非依赖冗长的提示词描述。

必要时保持可复用指令稳定，在不为了缓存收益而扭曲语义或改变指令优先级的前提下维持结构。声称性能改善前核实供应商的真实缓存行为。

交付已验证的行为变化、对比评估结果、实际执行证据和剩余限制。配置或集成结论使用 `test-evidence`；模型可用本身不能证明任务质量。
