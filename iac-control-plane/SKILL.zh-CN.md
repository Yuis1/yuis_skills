# IaC 控制面治理

建立并治理作为可重现控制平面的基础设施代码仓库。声明式代码定义期望目标意图，现场运行健康依赖带时间戳的新鲜证据，且变更必须受控于严格的爆炸半径边界。

## 入口分支门禁

- 建立或调整管理边界（新建仓库、云租户或 IaC 根目录）：阅读 [SCAFFOLD.zh-CN.md](SCAFFOLD.zh-CN.md)，建立仓库拓扑、变量层级与机密边界脚手架。
- 在既有边界内执行变更：直接遵循下方的运维生命周期工作流，执行日常变更、维护与验证。
- 纳管存量资源或处理未确认状态：在生成计划前，先核对现场事实与状态。

## 运维生命周期工作流

1. **界定范围与边界路由：** 将运维意图映射到其权威事实源：声明式配置、主机清单、主机标准、云平台运行手册、状态策略或机密边界。严禁维护多份操作策略或现场状态副本。
2. **审查调用方与前置条件：** 严格区分期望目标配置与带时间戳的历史观测。修改前检索现存维护待办中的未决缺陷。隔离目标变更并保留已有工作树修改，严禁擅自清理工作树，核验环境能力与既有授权。
3. **隔离机密并收敛爆炸半径：** 变更剧本仅指向窄范围清单，附带显式 `--limit` 目标过滤并利用 `serial` 分批执行。按信任边界隔离多云 OpenTofu/Terraform 根模块。将凭据收敛在本地或机密管理器边界内。
4. **预检并上下文绑定最小变更：** 应用变更前先行执行语法检查（`--syntax-check`）并生成绑定的只读计划文件（`tofu plan -out=tfplan`）。计划文件包含敏感数据，保存在私有目录中并由 `.gitignore` 排除，在证据中记录 `plan_sha256` 摘要并严格基于绑定摘要、目标身份与状态路径执行。
5. **直接验证证据并闭环待办：** 捕获原生退出码、`stdout` 与 `stderr`，核验 `PLAY RECAP` 满足零不可达与零失败主机。要求通过可收敛任务的二次运行提供幂等证明，不机械重放单次生命周期动作。若执行异常中止且状态未知，严禁盲目重试，先核对远端现场后再行恢复。共享记录中对敏感输出脱敏。更新单一维护待办，在门禁通过后即刻注销关闭条目。使用 `trash-cli` 移除废弃文件。

## 不可协商的架构不变量

- **人机共读单一真相：** 人类与智能体阅读完全一致的权威正文。前置可执行结论与命令；在后文展开连贯的架构背景、技术权衡与失败原因。严禁维护智能体专用的重复说明副本。文档使用指向权威代码与变量的指针，避免抄录动态参数表格。
- **声明式期望解耦实时现场：** 代码与变量描述期望目标配置，不代表实际服务健康状态；状态文件记录纳管元数据，不代表已核实的运行时事实。运维断言必须依赖新鲜且带时间戳的探针证据，并附带有效期限定义。
- **破坏性操作安全门禁：** 删除、销毁、磁盘移除、存储桶删除、账户注销与宽泛清单变更均视为破坏性操作。执行前必须出具受影响资源计划、绑定计划摘要并获得用户明确确认。严格区分状态变更（`stop`/`start`）与永久删除。
- **反自锁与带外恢复连续性：** 涉及可能切断管理连接的网络、防火墙或远程接入变更时，确保带外控制与恢复通道可用。在应用连通性变更前必须装载自动计时回退机制，仅在独立验证通过后方可停止回退定时器。
- **双层拦截守卫分工：** 严格遵守控制端类似 Destructive Command Guard（`dcg`）的安全拦截机制，严禁绕过或擅用豁免。将控制端守卫与目标机侧防护相结合，针对破坏性任务执行 `--check` 预演与显式标签控制。
- **三层机密防护边界：** 严禁提交明文机密、云服务账号密钥、私有 SSH 密钥与活动 `.env` 文件。控制端机密存放在 `.local-secrets/`（由 `.gitignore` 排除并跟踪 `*.example` 模板），运行时机密存放在加密 Vault 中，云自动化接入基于 `OIDC` / `WIF`。物理隔离人工、自动化与应急密钥。
- **状态基线与条件后端迁移：** 当状态仅有单个活动写入者时，OpenTofu/Terraform 状态文件默认保持本地、私有且受忽略；变更前必须在本地备份状态；将 `.terraform.lock.hcl` 纳入版本控制以确保 Provider 确定性解析。仅在经过评估的多人并发或审计需求下才引入远端锁定后端；严禁在同一次变更中将后端迁移与 Apply 或 Destroy 自动化混用。
- **CI 只读证据边界：** 持续集成工作流仅用于生成只读验证证据，绝不构成合并或生产变更的授权凭据。严禁全库配置任何自动化 Apply 或 Destroy 工作流。
- **单一维护待办台账：** 将未决基础设施缺陷、未竟迁移与硬件覆盖集中记录于单一维护待办台账。每条记录声明责任人、当前状态、可观测证据与明确的下一项验收门禁。验收门禁通过后立即删除闭环条目，避免堆积形式主义清单。
- **基于回收站的资产处置：** 普通文件移除统一使用 `trash-cli`。清空回收站属于永久删除，必须列明受影响路径与容量并单独获得显式授权。任务集成或废弃后，及时回收中间工作树与临时测试节点。

## 交付证据

- **权威变更差异：** 明确具体的配置、剧本或策略文件变更。
- **预检验证凭证：** 证明在声明范围内产生预期变动的语法检查、预演或计划输出。
- **真实执行证明：** 退出码为 `0` 的原生命令输出与带时间戳的验证记录。
- **残留清理处置：** 更新后的待办状态、证据文件归档路径与已核验的清理结果。
