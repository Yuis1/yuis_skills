# 遗留测试迁移

只在迁移测试 Owner、重建测试基础设施或删除大量旧测试与 Fixture 时读取。

## 先建立契约映射

逐项记录：

`行为 ID → 旧证据 → 新 Owner 的证据 → 处置`

将旧测试分为：

- 公开行为契约；
- 与私有实现耦合的检查；
- 重复场景；
- 仅为旧兼容路径服务的装配、Fixture 或转发。

不要按文件名、行数或测试数量机械迁移。

## 迁移顺序

1. 在删除前确认旧测试实际证明了什么。
2. 为公开行为指定新的权威测试位置。
3. 对既有行为，新测试原则上应在旧实现上通过，表明测试验证的仍是既有契约。
4. 对新增行为或架构切换契约，可以在旧实现上失败，但要说明失败代表什么。
5. 新权威证据通过后，才在同一切片删除重复测试、私有辅助函数、定位器、动态转发和旧 Fixture。
6. 运行受影响 Owner 与真实依赖闭包的验证，记录未迁移契约。

禁止先删除旧测试，再凭新实现或记忆重写。若无法证明某项旧测试是否仍有价值，先保留并登记待确认项。

## 测试基础设施

产品实现、测试基础设施重建和质量门规则默认使用独立 Diff。测试基础设施阻塞产品切片时，先冻结产品候选版本，再拆出作为前置条件的基础设施切片，避免把产品行为变化藏在大规模测试迁移中。
