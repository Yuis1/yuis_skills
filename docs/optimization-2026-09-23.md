# September 2026 instruction maintenance

## Scope

The accepted plan keeps nine skill identities, the existing model policy and manual model selection. Changes clarify triggers, remove obsolete instructions and reduce repeated global teaching. Existing project architecture contracts, default TDD, destructive-operation authorization, DCG and the merge/rebase abort prohibition remain binding.

## Changes and Retained Requirements

| Area | Change | Retained boundary |
|---|---|---|
| Global instructions | Shorter rules, task-sized reporting and selective workflows | User scope, current evidence, secrets, safe deletion, TDD and explicit authorization |
| Agent development | Checkable output units instead of an absolute one-pass ban and ambiguous React wording | Versioned comparison and semantic versus deterministic decisions |
| Agent teams | Current runtime interfaces, bounded recovery and one writer regardless of mode | Root-only delegation, explicit permissions and user model choices |
| System design | Clear write boundaries, pending outcomes and compact artifacts | Existing architecture baseline; structural decisions still read this skill |
| Evolution and enforcement | Actual coupling before labels; project checks before new pipelines | Compatibility, irreversible points, recovery and real compliant/violating examples |
| Refactoring | Completed slices retire old paths; checkpoints follow authorized workflow | No big-bang migration or unrelated cleanup |
| Evidence | Candidate impact analysis, direct contract checks and separate review/acceptance states | No fabricated success, no mock-to-production claims, regression protection |
| ChatGPT Web | Three conditions before any preflight: separable question, frontier/difficult topic and extensive literature | Existing CLI, account, confidentiality and submission boundaries |
| Visual skills | Remove brand-based routing and the original gpt-taste from managed installation | Existing product, design system, functionality and accessibility |

The detailed architecture rules moved out of the global file remain in `system-design`; they were not replaced with a universal exemption for scripts. The bilingual contract and English-only exception for `chatgpt-chat` are unchanged. Model suggestions remain owned by the separately generated `delegation-models` skill.

## Verification and Publication

Run the existing bilingual checker and its tests. Review obligation strength in both languages; structural parity is not semantic proof. Use the accepted plan's eight scenario classes to check triggers, retry uncertainty, permissions, visuals, manual model choice and protected user work. Record whether each result is a text review, a bounded agent decision or an executed integration; do not claim all three from one result.

Publish through yuis_ops to the local canary only. Existing skill links share a pinned source checkout, so updating that checkout also updates their content. Record the previous version, inspect local changes before checkout, verify instruction bytes and link targets, and check a second convergence. The runtime may need a new conversation to load updated instructions; publishing files is not proof of universal future behavior. Other machines keep their existing release until an explicit rollout.
