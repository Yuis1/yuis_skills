# 前沿大模型项目规划与重构实战横向评测（2026年11月）

本次基准评测针对六款前沿与高吞吐大语言模型，在一个真实、未发布且高度复杂的全栈工程项目（包含 Go、TypeScript 与 Dart 编写的单体仓库服务，生产与测试代码共约 69 万行）上，全面评估其自主系统规划与代码库重构能力。

为模拟普通开发者的真实使用场景，实验全程采用极简、无过度提示的输入指令，不提供任何预先整理的高密度架构总结，完全依赖项目既有的 `AGENTS.md` 与已安装的技能库（`agent-team`、`system-design`、`test-evidence`、`safe-refactor`）由智能体自主决策。

> **隐私与脱敏声明：** 恪守开源合规准则，报告对所有涉及的项目专有实体名称、具体业务术语与机器路径均已执行脱敏抽象。评测目标系统统一代称为 **Project-Alpha**（三阶段深度交互关系服务）。

## 1. 评测工程基准现状与架构全貌

评测目标工程库（**Project-Alpha**）是一个未发布的绿地全栈单体多包仓库，具备极其深厚的领域建模与厚重的测试治具：

- **后端核心服务 (`/services/core-api`)：** Go 1.27+，采用 Chi 路由、pgx 与 sqlc。包含 72 个领域包、191,877 行生产代码以及 35,050 行 HTTP 路由处理。单元测试、集成测试与并发测试共计 196,178 行。
- **数据库架构 Schema：** PostgreSQL 18，包含 319 张表、1,330 条 `CHECK` 约束、200 个触发器以及 26 张运维回执与审计表，已折叠为单一初始迁移文件（`00176_initial.sql`，共 25,847 行）。
- **共享 API 接口契约 (`/contracts`)：** 严格遵循契约先行，包含 147 份接口定义（135 份带版本号）、60+ 份 JSON Schema，并通过自动化测试治具校验 Golden 契约快照。
- **解耦的 AI 运行时 (`/services/agent-runtime`)：** 包含 29 个 TypeScript 文件（共 4,625 行），划分为 7 组无状态独立执行器，严格实行令牌命名空间隔离、闭环失败原则，且对业务数据库零直接写入权限。
- **跨端前端应用：**
  - *React Web 客户端 (`/client/web`)：* 约 20,000 行 TypeScript 代码，覆盖 90+ 个特性组件与深层路由。
  - *移动端 (`/client/mobile`)：* 采用 Flutter/Dart 编写，包含 252 个文件共 96,763 行，具备 Android 安全防截屏与 iOS 私有沙盒流式音频通道集成。
- **产品生命周期与核心状态机：**
  - *阶段一（寻找建档与初筛）：* 包含情境化测试题库、心理动力学评分机制与多层撮合管道。
  - *阶段二（专属协同相识舱）：* 14 天独占相识舱、阶梯式反脱媒拦截、阅后即毁时效多媒体流以及每日双盲促导卡。
  - *阶段三（长期伴侣协作系统）：* 动态生活公约、版本差异比对、周期性默契回顾以及结构化 NVC 降温调解。
- **过程资产与治理债务：** 累积了 547 个 Git 标签（含 240 个 `recovery/*` 标签）、23 个独立的端到端脚本、13 个单旅程治具程序、123 个多代版本化文件以及 1,598 处废弃注解。

## 3. 评测打分体系与各分项扣分矩阵

评测严格依据以下五个正交维度进行综合打分：

1. **绿地架构折叠与断舍离 (25%)：** 针对零生产用户系统，能否果断剔除虚构的 v1~v6 向后兼容垫片、历史快照列与废弃适配器，遏制治理膨胀。
2. **主干黄金路径优先度 (25%)：** 能否高度聚焦未经 Mock 的端到端核心用户闭环，并将 0.01% 的灾难场景、复杂边缘异常与推测性设计推迟至 `BACKLOG.md`。
3. **真实可执行性与单命令端到端验收 (20%)：** 能否将工作切解为原子任务契约（代码变更控制在 300 行以内，单任务 15~45 分钟），并具备唯一且无交互的单命令端到端真实验收指令。
4. **重依赖规则桩解耦意识 (15%)：** 对尚未校准的上游大模型或第三方商户接口，能否使用确定性规则桩进行解耦隔离，避免外部依赖阻塞里程碑集成。
5. **敏捷规范与看板纪律 (15%)：** 是否严格遵守极简 4 态看板（`TODO`、`IN_PROGRESS`、`DONE`、`BLOCKED`），杜绝发明仪式性总结与多阶段收尾文件。

## 5. 跨裁判视角对比：形式主义与实干主义的辩证交锋

为杜绝单一裁判主观偏见，两名资深独立裁判在完全未获知先前打分结论的前提下，基于相同评分准则独立出具了详尽裁决报告：

### 独立裁判一：`openai-codex/gpt-6-astra`（形式主义与不变量守卫者）
- **排名结论：** D 组 Kimi（84分）与 E 组 MiMo（82分）领先；A 组 Pi DeepSeek（61分）与 B 组 Gemini（44分）受罚。
- **核心论据：** Astra 严格站在形式化类型系统、事务隔离性与关系代数不变量视角审视。Astra 严厉批评了 A 组（Pi DeepSeek）“按数字指标强定删表上限”的指标化裁剪倾向，并指出数据库使用 `text + CHECK` 约束完全符合非法状态不可表示原则，断言“未用 enum 即违规”属于误判；对 B 组（Gemini）则因前后里程碑代号漂移以及引入过重的分布式 StateGraph 给予扣分；高度赞赏 D 组（Kimi）与 E 组（MiMo）在数据保留、字段追踪与单体装配上的严谨度。

### 独立裁判二：`deepseek-official/deepseek-flash`（实干主义与交付战术家）
- **排名结论：** A 组 Pi DeepSeek（88分）与 C 组 CodeBuddy DeepSeek（86分）并列第一梯队。
- **核心论据：** DeepSeek 严格以 Git 物理提交、事实核查与真实可交付性为基准。DeepSeek 独立回灌了全仓事实，证实 A 组是全场唯一通过实际命令测出 191k 行 Go 代码、319 张表、547 个标签并揪出 89/92 组件中文硬编码的模型；严厉批评 D 组（Kimi）耗时 15 分钟导致流水线瘫痪，并在执行层面重申主干黄金路径必须快步收敛。

## 6. 关键实战结论与选型指南

1. **Pi 原厂原生与代理网关对比 (`deepseek-flash`)：**
   - Pi 原厂原生通道在执行同样的 DeepSeek Flash 模型时，比代理网关**快 54 秒**（提速 25%），且前缀缓存命中率极高、自主排查能力更强。
2. **长推理（xhigh）在规划任务中的负面效应：**
   - Kimi K3.1 Pro 的超时印证了规划场景下无约束长推理容易引发“分析瘫痪”，反而是直球高吞吐模型能给出更清晰的交付边界。
3. **推荐生产配置策略：**
   - **战术任务切片与代码库审计：** 首选 Pi 原厂通道 `pi/deepseek-official/deepseek-flash`，其在任务契约拆解、历史负债切除与端到端单命令验收上表现无懈可击。
   - **顶层系统架构与状态机设计：** 首选 `pi/antigravity/gemini-3.8-flash`，其在宏观系统建模、形式化验证结构与全流程里程碑规划上具备断层领先的完整度。
   - **通用领域建模与平稳迭代：** `codebuddy/deepseek-v4.1-flash` 与 `codebuddy/mimo-v2.6-pro` 可作为集成开发环境内部的有力备用选择。
