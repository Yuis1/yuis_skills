# 2026 年 9 月指令维护

## 范围

已接受的计划保留九个技能身份、既有模型政策和手工模型选择。变更澄清触发条件、删除过时指令并减少全局重复教学。既有项目架构契约、默认 TDD、破坏性操作授权、DCG 和禁止中止 merge/rebase 的规则继续有效。

## 变更与保留要求

| 范围 | 变更 | 保留边界 |
|---|---|---|
| 全局指令 | 缩短规则，按任务汇报并选择流程 | 用户范围、当前证据、秘密、安全删除、TDD 和明确授权 |
| Agent 开发 | 用可检查单元替代绝对的一次输出禁令及含糊的 React 表述 | 版本化对照，以及语义和确定性决策的区分 |
| Agent 团队 | 当前运行器接口、有界恢复、不依赖模式的单写入方 | 仅根 Agent 派发、明确权限和用户模型选择 |
| 系统设计 | 明确写入边界、待确认结果及精简工件 | 既有架构基线；结构决策仍须读取该技能 |
| 演进与守护 | 先查真实耦合再用术语，先用项目检查再新增流水线 | 兼容性、不可逆点、恢复及真实合规／违规样例 |
| 重构 | 完成的切片减少旧路径，检查点服从已授权流程 | 不做大爆炸迁移或无关清理 |
| 证据 | 候选影响分析、直接契约检查、区分审查与验收状态 | 不伪造成功，不用 mock 证明生产行为，保留回归保护 |
| ChatGPT Web | 预检前同时满足三项：问题可分离、前沿或困难、需要大量文献 | 既有 CLI、账号、保密和提交边界 |
| 视觉技能 | 去掉按品牌路由，原版 gpt-taste 退出受控安装 | 已有产品、设计系统、功能与可访问性 |

从全局文件下沉的架构细则仍在 `system-design`，没有被“脚本一律豁免”替代。双语契约和 `chatgpt-chat` 仅英文的例外保持不变。模型建议仍由单独生成的 `delegation-models` 技能负责。

## 验证与发布

运行既有双语检查及其测试。复核两种语言的义务强度；结构一致不是语义证明。使用已接受计划的八类场景检查触发、重试不确定性、权限、视觉、手工模型选择和用户工作保护。记录结果属于文本审查、有界 Agent 决策还是实际集成执行，不能由一种结果声称三者全通过。

通过 yuis_ops 仅发布到本机试点。已有技能链接共用固定版本源码 checkout，更新它也会更新链接所读内容。记录旧版本，checkout 前检查本地改动，验证指令字节和链接目标，并检查第二次收敛。运行器可能需要新会话才能加载更新；文件发布不能证明所有未来行为。其他机器保留当前发布版本，等待明确下发。
